3. 冻结后的 API 和业务口径

3.1 #3500 字段契约

数据库原始字段固定为：

字段 含义
title 中文原始名称，保存前 trim
title_en 英文原始名称，保存前 trim
deleted 软删除标记，0 为未删除

管理列表和引用详情统一返回：

字段 含义
name 当前语言展示值，保留旧接口语义
name_en 英文原始名称，直接映射 title_en，列表和详情都必须返回

不新增 title_zh，避免 title/title_zh 两套中文原始字段。编辑表单只能使用 title 和 name_en 回显；name、display_name 只能展示，不能回写数据库。

展示语言规则：

  1. zh_CN、zh_TW、zh-cn、zh-tw 优先 title，中文为空时回退 title_en。
  2. 其他语言优先 title_en，英文为空时回退 title。
  3. 两者都为空返回 --，异常日志限频。
  4. 不再调用 AI 翻译，不再按固定中文名称映射；监管类型输入不得使用会删除英文标点的中文清洗函数。

3.2 #3501 查询输入

列表新增 invite_code 查询字段，同时兼容页面已有 keyword。输入归一化规则：

  1. trim；空字符串不查询。
  2. 普通 query 和 hash query 都解析，例如 login/register?ref=ABC、#/login/register?invitation_code=ABC。
  3. 支持 ref、invitation_code、invitationcode；多个别名值不一致返回参数错误。
  4. URL 没有邀请码时返回“邀请链接无法解析”，不能降级为模糊搜索。
  5. 纯正十进制数字只按会员 ID 处理；不接受正负号、科学计数法或空格混合数字。
  6. 非数字按 t_member_invent_code.code 精确匹配，沿用当前数据库排序规则。
  7. 邀请码与客户类型、层级、注册时间等筛选使用 AND 关系。

3.3 #3501 主列表和层级

本期明确接受一次行为变化，避免依赖旧代码中的隐式条件：

  • 管理员在无 parent_id、无关键词时查询 parent_id=0 的主列表；关键词查询允许命中任意后代，仍受显式客户类型和层级条件限制。
  • 非管理员在无 parent_id、无关键词时查询 parent_id=当前登录会员 ID 的第一层；关键词查询仍用 member_root_path.path 限制在数据范围内。
  • 传入 parent_id 时只查询该父会员的直属启用会员，用于展开；展开不继承新的关键词，避免把搜索结果误当成树节点。
  • 列表固定保留 a.status=1，本期删除 member_invalid 状态；无效会员不会从正常列表进入明细。
  • 账号列表继续排除当前登录会员。明细接口对非管理员也按同一规则排除本人；若未来要允许查看自己的邀请码，应另行修改产品口径和测试。
  • 邀码精确命中时返回命中会员本身，不受主列表顶层条件影响，但必须通过同一数据权限检查。

列表新增字段：

字段 口径

4. #3500 数据库实施方案

4.1 发布前检查顺序

当前两个数据字典的 t_kyc_regulatory_type 都没有 title_en，所以禁止在检查字段前引用它。测试、预发、生产都按以下顺序执行：

  1. SELECT VERSION()。发布闸门要求 InnoDB 且 MySQL >= 5.7.6（支持 STORED generated column 和索引）；低于此版本阻断发布，不切换另一套实现。
  2. 查询 information_schema.columns 确认 title_en、生成列和现有索引是否存在。
  3. 在 title_en 不存在时，只检查中文重复、中文空值和现有索引；跳过所有英文字段 SQL。
  4. 通过迁移脚本增加 title_en。
  5. 字段存在后，再执行英文重复检查。
  6. 重复数据只生成清理清单，人工确认保留记录和改名方案；不能在迁移中自动删除、覆盖或截断。
  7. 清理完成后，再添加生成列和唯一索引。

中文检查必须与生成列表达式完全一致：

1SELECT TRIM(title) AS normalized_title, COUNT(*) AS cnt
2FROM t_kyc_regulatory_type
3WHERE deleted = 0
4GROUP BY TRIM(title)
5HAVING COUNT(*) > 1 OR normalized_title = '';

增加 title_en 后执行：

1SELECT LOWER(TRIM(title_en)) AS normalized_title_en, COUNT(*) AS cnt
2FROM t_kyc_regulatory_type
3WHERE deleted = 0 AND TRIM(title_en) <> ''
4GROUP BY LOWER(TRIM(title_en))
5HAVING COUNT(*) > 1;

4.2 唯一的默认 DDL 方案

不提供命名锁或“按数据库版本临时换方案”的备选。迁移程序通过 information_schema 判断后逐条执行下列固定定义；发现同名字段/索引但定义不同，立即停止并人工处理。

 1ALTER TABLE t_kyc_regulatory_type
 2  ADD COLUMN title_en VARCHAR(100) NOT NULL DEFAULT ''
 3    COMMENT 'KYC监管类型英文原始名称' AFTER title;
 4
 5ALTER TABLE t_kyc_regulatory_type
 6  ADD COLUMN title_active_norm VARCHAR(255)
 7    GENERATED ALWAYS AS (
 8      CASE WHEN deleted = 0 THEN TRIM(title) ELSE NULL END
 9    ) STORED
10    COMMENT '未删除监管类型中文唯一归一值',
11  ADD COLUMN title_en_active_norm VARCHAR(100)
12    GENERATED ALWAYS AS (
13      CASE
14        WHEN deleted = 0 AND TRIM(title_en) <> ''
15        THEN LOWER(TRIM(title_en))
16        ELSE NULL
17      END
18    ) STORED
19    COMMENT '未删除监管类型英文唯一归一值';
20
21ALTER TABLE t_kyc_regulatory_type
22  ADD UNIQUE KEY uk_kyc_regulatory_type_active_title (title_active_norm),
23  ADD UNIQUE KEY uk_kyc_regulatory_type_active_title_en (title_en_active_norm);

说明：

  • title_active_norm 对未删除记录使用 TRIM(title)；删除记录返回 NULL，允许名称复用。
  • title_en_active_norm 对未删除且非空英文使用 LOWER(TRIM(title_en))；空英文返回 NULL，允许多条空值；LOWER 保证英文大小写不敏感。
  • 预检查、Service 查重和唯一索引使用同一归一化表达式。
  • 生成列不加入 Model 写入白名单，不出现在 API 契约中。
  • MySQL DDL 自动提交，迁移文件按“字段 -> 生成列 -> 索引”顺序执行；任一步失败立即停止，不继续后续 DDL。

4.3 幂等实现

不依赖 ADD COLUMN IF NOT EXISTS 或 CREATE INDEX IF NOT EXISTS。版本 SQL 或迁移命令逐项读取 information_schema：

  • 字段不存在：执行对应 ADD COLUMN。
  • 字段存在且定义完全一致：跳过。
  • 字段存在但类型、表达式、生成方式不一致：阻断并输出差异。
  • 索引不存在：执行 ADD UNIQUE KEY。
  • 索引存在且列顺序、唯一属性一致：跳过。
  • 索引存在但定义不一致：阻断，不自动删除或重命名。

该索引只服务 member_id 精确过滤和 groups 关联；发布前必须用真实测试数据 EXPLAIN 邀请码精确查询、当前页批量摘要和明细查询。若索引已存在且定义一致则跳过。

t_ib_invite_link_config 是必需依赖，不是条件依赖。两个数据字典补入历史 SQL 中的完整结构：

  • id 主键；
  • server_id、account_type、register_group 快照字段；
  • account_register_setting_id 关联 account_register_setting.id，唯一索引 uk_account_register_setting_id；
  • global_enabled、status_description、操作人和时间；
  • uk_server_account_setting、idx_server_enabled、idx_account_type_enabled、idx_register_group、idx_updated_at。

无配置记录时沿用 IbInviteLinkConfigService 和用户端当前代码的默认启用口径；不能把 LEFT JOIN 改成内连接，不能因后台没有开关记录而隐藏历史邀请码。

5. #3500 后端实施步骤

  1. 验证器和 Service：新增 name_en 校验；中文和英文均 trim，英文允许正常名称所需标点和括号；应用层查重后捕获数据库 23000，统一返回“名称已存在”。新增、编辑、审计日志在同一事务；删除和软删除逻辑不变。
  2. 展示辅助方法：在 KycRegulatoryTypeService 内集中实现 normalizeRawNames、displayName 和批量字典映射。方法注释说明语言回退、空值和不启动翻译任务。
  3. 管理列表/详情：getList、references 同时选择 title/title_en，返回 name/name_en/title/display_name；references 的名称快照和列表一致。
  4. KYC 设置：KycSetting::paginateForAdmin() 选择英文列；调用层统一输出 regulatory_type（展示）和 regulatory_type_en（原始英文）。不改变 ID 关联。
  5. 支付渠道：Pay::index() 的 regulatory_type_list 返回完整字典；Pay::save() 仍只校验 ID，不能接受客户端提交名称。
  6. 客户列表、详情和导出：盘点 Member.php 中所有 kyc_regulatory_type_id、auth_kyc_supervise 和导出入口，收集当前页 ID 后一次查询名称映射；响应增加英文字段，避免循环查表。
  7. 日志：SystemOperationLogService 在操作发生时把 title、title_en 保存到 change_data 的旧值/新值；Logs.php 只翻译 field_i18n_key，不根据当前语言重新查询监管类型，因此历史日志不会漂移。
  8. 删除固定翻译：删除 kycRegulatoryType.js 的固定标题映射和后端 AdminTranslationKvService::queueTexts() 调用；保留未知名称原文和 -- 占位。

6. #3501 后端实施步骤

6.1 文件和职责

新增：

  • gtc_admin/app/admin/model/MemberInviteCode.php：t_member_invent_code 的字段白名单和只读查询入口。
  • gtc_admin/app/service/AgentAccountInviteCodeService.php：输入解析、列表范围、摘要批量查询、明细展开、状态计算、排序和权限前置检查。

修改：

  • gtc_admin/app/admin/controller/Agent.php：account() 委托 Service；新增 invite_code_details()，只负责参数验证、URL 权限和统一响应。
  • gtc_admin/app/admin/common.php 不改公共 check_data_permission()；Service 显式补充“本人不在本列表”的规则。
  • gtc_admin/app/admin/model/Member.php 如需批量会员摘要，复用现有批量方法，不在循环内新增查询。

新接口的权限映射必须在 Agent Controller 的 permissionAlias 或菜单节点中显式配置，默认复用 agent/account 查看权限；不能只在文档写“沿用权限”。

6.2 查询和权限

列表查询先建立会员驱动结果集，再批量读取邀请码和配置：

  1. member + member_root_path 按主列表规则分页，固定 status=1。
  2. 当前页会员 ID 一次查询 t_member_invent_code WHERE member_id IN (...)，计算 invite_code_count 和摘要。
  3. 当前页会员 ID 一次查询直属下级 member WHERE status=1 AND parent_id IN (...)，生成 has_children。
  4. 只有展开请求才按单个 parent_id 分页取一层子列表。
  5. 关键词为邀请码/会员 ID 时先得到命中会员 ID，再套数据权限；管理员也不能绕过接口权限。

明细接口顺序固定为：参数解析 -> URL 权限 -> 会员存在且 status=1 -> check_data_permission() -> 非管理员排除本人 -> 验证 matched_invite_code -> 批量读取该会员全部 code -> 读取配置和平台开关 -> 状态计算。任何越权都返回统一无权限错误，不泄漏 code 是否存在。

6.3 只读状态计算

状态计算只读 t_member_invent_code、member、account_register_setting、member_agent_remark、t_ib_invite_link_config、服务器配置，不调用 gtcuser，不写入邀请码、不补建配置、不修改状态。

每个 code 的 status 为 enabled 或 disabled。多个配置中任意一行可用时 code 汇总为 enabled；全部不可用时返回去重后的 disable_reasons，优先顺序为 ib_disabled、platform_disabled、config_invalid、authorization_invalid。服务端记录 reason，前端只展示多语言文案。

7. #3501 前端实施步骤

修改：

  • gtc_admin_vue/src/api/agent/index.js
  • gtc_admin_vue/src/views/agent/account/index.vue
  • 同目录拆分出的查询/明细组件和多语言资源（如仓库现有结构需要）

页面验收口径：

  1. 查询框支持邀请码、会员 ID、完整链接；解析失败、未找到归属用户、无符合条件用户、列表加载失败分别显示可重试的空状态，并保留当前查询条件。
  2. 昵称区域按“展开/收起图标 + 昵称 + 客户类型 + 客户 ID”展示；代理使用现有 IB/代理标签，直客使用现有直客标签。
  3. has_children=true 显示可点击展开图标；false 显示灰色不可点击占位图标，不发送请求。
  4. 展开请求只加载一层直属下级，收起不清空主查询条件；过期响应不能覆盖最新列表。
  5. 明细顶部显示昵称、用户类型、客户 ID、去重邀请码总数；items 多配置可多行，缺失配置保留占位并排在有效配置后。
  6. 英文监管名称允许常见英文标点和括号；字段缺失保留列位置并显示 --，不能因单个字段为空破坏行布局。
  7. 旧列表字段和分页行为保持兼容；新增字段缺失时前端按空值占位，不把 children=[] 误认为存在下级。

8. 测试和验收

8.1 #3500

  • 数据迁移：在没有 title_en 的数据库上按检查顺序执行；重复执行幂等；低版本 MySQL 阻断；定义不一致阻断。
  • 唯一性：中文 trim 后重复、英文大小写/trim 后重复、软删除后复用、并发新增和并发编辑。
  • API：列表和引用详情都断言 name、name_en、title、display_name；编辑回显使用原始 title/name_en。
  • 展示：中文、英文、繁体、缺失回退、双空 --；KYC、支付、客户、政府监管、导出和日志逐入口验证。
  • 日志：新增和变更保存中英文快照；切换后台语言后历史值不改变，字段标签正常翻译。

8.2 #3501

  • 输入：普通 query/hash query、三个别名、别名冲突、空链接、非法数字、精确 code、会员 ID。
  • 权限：管理员、非管理员第一层、后代关键词、越权会员、本人明细被拒绝；URL 权限缺失被拒绝。
  • 状态：code 停用、公开配置、授权配置、无授权、无有效配置、IB 总开关关闭、无开关记录默认启用、ACCOUNT_TYPE 不匹配。
  • 数据：一个 code 多配置、多 code、重复配置 ID、无配置历史 code；invite_code_count 与 items 行数口径不同。
  • 副作用：查询前后 t_member_invent_code 数量和内容不变，不调用自动补建链路。
  • 层级：管理员主列表/关键词、非管理员第一层、展开无下级占位、has_children 批量查询无 N+1。
  • 性能：对 code 唯一索引、idx_member_groups、member_root_path、parent_id 查询执行 EXPLAIN；列表不做大范围全表 count 或无界明细。
  • 前端：所有空状态、加载失败重试、字段缺失、类型和客户 ID、禁用展开图标。

9. 发布顺序、回滚和风险

9.1 发布顺序

  1. 备份受影响表结构和重复数据清单，确认 MySQL 版本。
  2. 发布数据字典和独立 SQL 文件；先完成 #3500 字段、生成列和索引，再确认 #3501 依赖表/索引。
  3. 先发布后端兼容版本：能读取旧表、title_en 为空时回退，能识别旧列表请求。
  4. 发布前端和新详情接口。
  5. 灰度验证列表、详情、日志、权限、状态和 EXPLAIN，再全量。

9.2 回滚

  • 应用回滚：先回滚前端，再回滚后台代码；旧代码读取 title 不受 title_en 影响。
  • 数据回滚：只有确认新字段和生成列未被后续写入依赖时，才按“索引 -> 生成列 -> title_en”逆序删除；默认保留新增字段和历史英文数据，优先应用回滚，不执行破坏性 DROP。
  • #3501 索引回滚只删除本次新增且确认无其他版本依赖的索引；不删除 t_ib_invite_link_config 或历史数据。
  • 迁移任何一步失败即停止并记录已完成步骤，不重复执行未确认的 DROP/ALTER。

9.3 剩余风险

  • 未读取生产数据量、线上 MySQL 版本和真实执行计划；发布前必须补齐。
  • member、account_register_setting 等历史表的真实索引可能与数据字典有差异，必须以目标环境 SHOW CREATE TABLE/SHOW INDEX 为准。
  • 本期后台规则通过契约测试保持与用户端一致；若用户端未来增加注册条件，需要同步更新契约测试和后台只读计算。

10. 开发拆分和完成标准

  1. DB 任务：#3500 字段/生成列/唯一索引、#3501 邀请码索引、t_ib_invite_link_config 数据字典；通过幂等和重复数据检查。
  2. 后台 #3500：Service/Model/Validator/Controller、KYC/支付/客户/政府监管/导出/日志调用链；返回字段契约通过。
  3. 后台 #3501：Agent Controller、MemberInviteCode Model、AgentAccountInviteCodeService、权限和批量查询；状态契约通过。
  4. 前端：监管类型中英文表单/列表/详情、IB 查询/展开/明细/空状态；前端构建和页面验收通过。
  5. 测试与发布：PHP 8.2.35/8.1 语法检查、现有相关测试、契约测试、EXPLAIN、灰度清单和回滚记录齐全。

在上述条件全部满足前，方案不得标记为“可发布”。本 v2 仅作为实施主文档，v1 文件保留用于评审历史。
