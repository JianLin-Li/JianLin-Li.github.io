会员敏感字段加密开发指南

2026-10-29 项目：gtc_admin

会员敏感字段加密开发指南（CRM / gtcuser）

关键词：t_member.phone、t_member.identity、t_member_other、手机号、证件号、shadow_strict、shadow_only。

本文按 2026-10-12 两个项目的 master 代码核对。生产和 staging 已采用 shadow_strict + shadow_only、主表历史明文已清空这一运行现状由部署方确认；仓库里的示例环境文件不代表线上实时配置。本文是开发调用说明，不是授权开发者扩大手机号或证件号的可见范围。

1. 先看配置

两个项目各自读取 member_sensitive 配置：CRM 为 config/member_sensitive.php，gtcuser 为 config/autoload/member_sensitive.php。部署时两端必须使用同一版本号和同一组四把密钥；不要在文档、工单、代码或日志中填写真实密钥。

环境变量 含义
CRM_SENSITIVE_KEY_VERSION_CURRENT 当前密钥版本；写入的新密文和 HMAC 使用此版本。格式为小写字母或数字开头，后续可含小写字母、数字、_、-，总长 1-12。
CRM_SENSITIVE_PHONE_ENC_KEY_CURRENT 手机号加密密钥。
CRM_SENSITIVE_PHONE_HMAC_KEY_CURRENT 手机号完整值精确查询的 HMAC 密钥。
CRM_SENSITIVE_IDENTITY_ENC_KEY_CURRENT 证件号加密密钥。
CRM_SENSITIVE_IDENTITY_HMAC_KEY_CURRENT 证件号完整值精确查询的 HMAC 密钥。
CRM_SENSITIVE_KEY_VERSION_PREVIOUS 及对应的 PHONE_ENC_KEY_PREVIOUS、PHONE_HMAC_KEY_PREVIOUS、IDENTITY_ENC_KEY_PREVIOUS、IDENTITY_HMAC_KEY_PREVIOUS（均以 CRM_SENSITIVE_ 开头） 上一版本；尚未轮换时五项同时为空。轮换期间五项必须同时有效，不能只填版本号，也不能在旧密文尚存时删除。
CRM_SENSITIVE_READ_MODE 当前为 shadow_strict：从影子读取，影子行缺失、字段不成对、密文解不开或 HMAC 不匹配即失败，不回退主表。
CRM_SENSITIVE_WRITE_MODE 当前为 shadow_only：敏感值写入影子，同时清空本次涉及的主表 phone/identity。代码要求它必须与 shadow_strict 搭配。

四把 current 密钥彼此独立，均为无 padding 的 Base64URL 编码、解码后 32 字节；previous 若启用也必须满足同样条件，且不得复用任何 current 密钥。代码固定 protocol_version=v1、normalizer_version=v1，运行环境须有 PHP sodium 扩展。legacy、compare、shadow_fallback 和 legacy_only、dual_write 是迁移兼容模式，不是当前运行配置。gtcuser 配置文件仍有 legacy/dual_write 缺省值，因此部署环境必须显式设置两项模式，不可依赖缺省值。改环境变量后应按各项目的部署方式重新加载进程/配置，避免旧 worker 继续使用旧值。

2. 数据怎么存、怎么读

表/列 当前用途
t_member.id 会员主键；读取和加密都绑定这个 ID。
t_member.phone、t_member.identity 历史兼容列；已清空，不是手机号/证件号的数据源，也不能用于存在性判断、搜索或对外响应。
t_member.d_code、t_member.phone_verify 手机区号和验证状态等伴随业务字段；不等于手机号明文。
t_member_other.member_id 关联会员；每个会员的影子行必须存在，包括两个敏感值都为空的会员。
phone_ciphertext、identity_ciphertext 版本化、可认证的加密值；仅统一服务解密。
phone_hmac_index、identity_hmac_index 版本化 HMAC 盲索引，只支持完整值精确匹配；不是可读明文，也不支持 LIKE/前缀/后缀搜索。索引非唯一，查询可能命中多个会员。

影子字段为空时，其密文和 HMAC 成对为 NULL。影子整行不存在不是“手机号为空”，严格读取会报错。手机号规范化仅移除常见展示分隔符并结合已有 d_code 形成稳定值，不验证真实号码；证件号仅 trim 首尾空白，保留大小写和内部字符。业务格式校验仍在各入口执行，不要自己拼 SQL、计算 HMAC、调用 sodium 或把一名会员的密文复制到另一名会员（密文认证绑定会员 ID 和字段）。

选入口： CRM 读会员行用 MemberSensitiveService::hydrateMemberRow(s)；CRM 精确搜索用 findMemberIdsByExactPhone/Identity()。gtcuser 按 ID 读用 MemberSensitiveProfileService::readFields/readFieldsBatch()；精确搜索用 MemberSensitiveGateway::queryPhone/queryIdentity()。这两个项目的业务代码都不应直接读取 t_member_other 的密文或自行解密。gtcuser 的 Gateway 当前委托本地 MemberSensitiveLocalService 访问共用数据库，不是 HTTP 调用 CRM；旧注释中出现的“CRM read-batch”指保留的协议/类名，不代表网络请求。

3. CRM（gtc_admin / ThinkPHP）

核心类：app/service/MemberSensitiveService.php；已有范例可查 app/admin/controller/Member.php 的会员详情、会员列表、精确筛选及保存流程。以下代码中的 $memberId、$phoneInput、$identityInput 均应来自已完成授权和业务校验的调用上下文。

3.1 按会员 ID 读取手机号和证件号

 1use app\service\MemberSensitiveService;
 2use think\facade\Db;
 3
 4$row = Db::name('member')
 5    ->where('id', $memberId)
 6    ->field('id,phone,identity,d_code,phone_verify')
 7    ->find();
 8if (!$row) {
 9    // 使用当前业务入口原有的“会员不存在”处理。
10    throw new \RuntimeException('会员不存在');
11}
12
13/** @var MemberSensitiveService $sensitive */
14$sensitive = app()->make(MemberSensitiveService::class);
15$row = $sensitive->hydrateMemberRow((array)$row, ['phone', 'identity']);
16$phone = $row['phone'];       // 明文字符串；没有手机号时为 ''
17$identity = $row['identity']; // 明文字符串；没有证件号时为 null

hydrateMemberRow() 要求行内有有效 id（或 member_id）；只会替换请求的字段，普通字段仍由原行提供。只需要手机号时传 ['phone']，只需要证件号时传 ['identity']。返回的是明文，只在授权的业务环节使用；对外列表先还原再按现有权限和脱敏规则处理，不要直接把未脱敏值写进响应或日志。严格模式影子异常会抛 app\exception\MemberSensitiveException，不要捕获后改用 $row['phone']/$row['identity']。

3.2 已分页列表批量还原

 1use app\service\MemberSensitiveService;
 2
 3// $list['data'] 是现有查询分页后的数组；每行必须保留 id。
 4/** @var MemberSensitiveService $sensitive */
 5$sensitive = app()->make(MemberSensitiveService::class);
 6$list['data'] = $sensitive->hydrateMemberRows(
 7    (array)($list['data'] ?? []),
 8    ['phone', 'identity']
 9);
10// 按该接口已有的权限和脱敏流程处理后，再返回给调用方。
11$list['data'] = hideListEmailPhone($list['data'], ['email', 'phone', 'identity']);

这是 app/admin/controller/Member.php 现行列表顺序：先分页、再批量还原、最后脱敏。空列表直接返回空数组。不要在列表循环中逐个调用单行还原，也不要为展示少量数据先读全量会员。hydrateMemberRows() 自身没有 100-ID 的入参上限，但应只给已限制大小的页面/批次，避免单次巨量查询、解密和响应。

3.3 按完整手机号或证件号搜索

 1use app\service\MemberSensitiveService;
 2use think\facade\Db;
 3
 4/** @var MemberSensitiveService $sensitive */
 5$sensitive = app()->make(MemberSensitiveService::class);
 6$phoneIds = $sensitive->findMemberIdsByExactPhone($phoneInput, $dCode); // $dCode 可为 null
 7$identityIds = $sensitive->findMemberIdsByExactIdentity($identityInput);
 8
 9// 业务筛选继续按原规则叠加；空结果不能省掉条件后变成“查全部”。
10$eligible = $phoneIds === [] ? [] : Db::name('member')
11    ->whereIn('id', $phoneIds)
12    ->whereIn('status', [0, 1])
13    ->column('id');

两个方法均返回全部匹配会员 ID，不是单个会员。重复绑定、状态/权限、区号、是否允许同号等规则由调用业务处理；无结果时用空结果或不可能命中的 ID 条件，不能省略筛选。输入不是完整有效值时可能抛 MemberSensitiveException::NORMALIZATION_FAILED；应转换为该入口原有的参数错误，其他异常继续上抛。通用搜索参数含 phone 时，可参考 resolveExactPhoneSearchParams()，先移除通用 LIKE 条件再使用返回的 member_ids。

3.4 更新与创建，不直接改主表敏感列

 1use app\service\MemberSensitiveService;
 2
 3/** @var MemberSensitiveService $sensitive */
 4$sensitive = app()->make(MemberSensitiveService::class);
 5$result = $sensitive->writeMemberSensitiveFields(
 6    $memberId,
 7    ['phone' => $newPhone, 'identity' => $newIdentity],
 8    [
 9        'd_code' => $dCode,
10        'source' => 'your_business_action',
11        'sync_phone_verify' => true,
12    ]
13);
14// $result['changed_fields']、$result['after'] 是业务值；不要整体记录到日志。

changes 中未出现的字段保持原值；null/空字符串表示明确清空该字段。仅修改手机号就只传 phone，不要把 identity => null 当默认值传入。source 使用稳定的业务来源名；手机号 d_code、phone_verify 按当前入口的规则传。服务在短事务中更新影子，并把本次写入的主表敏感列保持为空。

创建会员时复用 MemberSensitiveMemberCreateService，即使两个敏感值都为空，也要显式传入字段键：

 1use app\service\MemberSensitiveMemberCreateService;
 2
 3$memberData['phone'] = $submittedPhone ?? '';
 4$memberData['identity'] = $submittedIdentity ?? null;
 5/** @var MemberSensitiveMemberCreateService $createService */
 6$createService = app()->make(MemberSensitiveMemberCreateService::class);
 7$newMemberId = $createService->create($memberData, [
 8    'source' => 'your_business_action',
 9    'd_code' => $dCode,
10]);

它在首次 INSERT 前剥离 phone/identity，同一事务拿到会员 ID 后交给敏感服务写入并建立影子行。若两键都省略，该服务不会调用敏感写入，也就不能保证影子行存在；严格读取即使对空手机号也会因缺行失败。异常应触发整笔回滚，不能自行先插入明文再补影子。原有业务副作用仍由创建调用方负责。

需要稳定逐项状态而不是还原会员行时，可调用 readMemberSensitiveBatch($ids, ['phone', 'identity'])。它单次只接受 1-100 个、唯一的正整数 ID；每项返回 member_id/status，成功项含请求字段及 source，失败项含 error_code，不能把失败项当空值。普通 CRM 列表优先用上述 hydrateMemberRows()。

4. gtcuser（Hyperf）

业务读取入口：App\Service\member\MemberSensitiveProfileService；按完整值查询/写入的门面：App\Service\crm\MemberSensitiveGateway。当前代码常通过 di()->get(...) 取得服务；已有范例见 app/Service/member/TMemberService.php、app/Http/Api/Controller/V1/SaleforceController.php、app/Service/member/MemberSensitivePhoneService.php、app/Service/member/MemberSensitiveIdentityService.php。

4.1 按 ID 读取一个会员

1use App\Service\member\MemberSensitiveProfileService;
2
3/** @var MemberSensitiveProfileService $profile */
4$profile = di()->get(MemberSensitiveProfileService::class);
5$values = $profile->readFields((int)$memberId, ['phone', 'identity']);
6$phone = (string)($values['phone'] ?? ''); // 当前业务需要字符串时显式转换
7$identity = $values['identity'] ?? null;

readFields() 只返回请求字段；当前本地严格读取中空 phone 为 ''、空 identity 为 null，调用方仍应按现有接口类型约定显式转换。读取失败抛 App\Exception\MemberSensitiveGatewayException，不会回退主表。已有公开会员资料接口用 TMemberService::readSensitiveFieldsForResponse($memberId, ['phone', 'identity']) 包装该调用，将内部异常转换为通用服务繁忙业务错误；新公开接口应沿用所属业务域已有的异常映射，不把内部机器码、会员敏感值或异常上下文直接返回客户端。

4.2 列表批量读取并覆盖响应字段

 1use App\Service\member\MemberSensitiveProfileService;
 2
 3$rows = array_map(static fn ($row): array => (array)$row, $pageRows); // 已分页的会员行
 4$memberIds = array_values(array_unique(array_filter(
 5    array_map('intval', array_column($rows, 'id')),
 6    static fn (int $id): bool => $id > 0
 7)));
 8/** @var MemberSensitiveProfileService $profile */
 9$profile = di()->get(MemberSensitiveProfileService::class);
10$sensitiveMap = $profile->readFieldsBatch($memberIds, ['phone', 'identity']);
11foreach ($rows as &$row) {
12    $id = (int)$row['id'];
13    $row['phone'] = (string)($sensitiveMap[$id]['phone'] ?? '');
14    $row['identity'] = $sensitiveMap[$id]['identity'] ?? null;
15}
16unset($row);
17// 继续执行该接口已有的权限、脱敏和响应组装逻辑。

readFieldsBatch([]) 返回 []，非空 ID 应先转正整数、去重。方法内部自动每 100 个 ID 分批，最终返回以会员 ID 为键的映射；任一项缺失/失败会抛异常，调用方不能用主表值降级。自动分批不是允许一次传入无限量 ID：先做业务分页/限定，尤其不要为一个大团队先拉取全部会员再批量解密。直接调用底层 MemberSensitiveGateway::readBatch() 时没有自动拆批，要求 1-100 个唯一正整数 ID、非空且不重复的 phone/identity 字段列表。

4.3 精确查询及业务规则

1use App\Service\crm\MemberSensitiveGateway;
2
3/** @var MemberSensitiveGateway $gateway */
4$gateway = di()->get(MemberSensitiveGateway::class);
5$phoneMemberIds = $gateway->queryPhone($phoneInput, $dCode); // 可选区号上下文
6$identityMemberIds = $gateway->queryIdentity($identityInput);
7// 返回全部匹配 ID；再交给当前业务的状态/权限规则筛选，不要取 first() 当唯一结果。

登录、注册、换绑、KYC 已有更窄的业务服务：MemberSensitiveLoginService、MemberSensitiveRegistrationService、MemberSensitivePhoneService、MemberSensitiveIdentityService。在这些流程里优先复用业务服务，避免绕过重复手机号处理、状态限制或短信验证。身份号精确匹配保留大小写；不得改成模糊搜索，也不得查 TMemberRepository 里的旧主表字段。

4.4 写入及特殊的注册失败语义

1use App\Service\member\MemberSensitivePhoneService;
2
3/** @var MemberSensitivePhoneService $phoneService */
4$phoneService = di()->get(MemberSensitivePhoneService::class);
5$normalizedPhone = $phoneService->writeVerifiedPhone($memberId, $newPhone, $dCode);
6// 仅在完成原有短信验证和重复绑定检查的业务流程中调用。

证件号 KYC 更新复用 MemberSensitiveIdentityService::syncIdentityChange($memberId, $memberChanges)，它会从普通更新数组移除 identity 并交给敏感门面写入。其他确需新增写入入口时参考 MemberSensitiveGateway::write($memberId, ['phone' => ['value' => $phone, 'd_code' => $dCode, 'sync_phone_verify' => true], 'identity' => ['value' => $identity]])；不要直接更新 t_member.phone/identity 或影子四列，也不要绕过已有业务前置校验。当前 shadow_only 由本地服务在短事务内写影子并保持本次主表敏感列为空。

注册是特例：MemberSensitiveRegistrationService 先创建空敏感主记录和影子行，再尝试同步提交的敏感值。同步失败时注册仍成功，本次手机号/证件号视为未绑定，安全日志事件为 member_sensitive_registration_sync_failed。排查时按会员 ID、注册流程、错误码等安全元数据定位；原始提交值未落盘，不能靠历史 backfill 恢复，须由后续受验证的业务入口重新提交。不要把这种失败解释为“影子成功但读取为空”。

5. 错误处理、验收和变更检查

  • CRM 严格还原失败会抛 MemberSensitiveException；CRM readMemberSensitiveBatch() 和 gtcuser 底层 readBatch() 则按项返回 status=error/error_code；gtcuser 的 ProfileService 把任何失败转成 MemberSensitiveGatewayException。MISSING_SHADOW/SHADOW_MISSING、字段不成对、解密或 HMAC 失败、未知密钥版本都应按故障处理，不能当成合法空值。
  • 读取前保持原接口授权、数据范围和脱敏规则；敏感原文只在必要的内存路径中使用。不要将原文、密钥、密文、HMAC、完整 SQL/请求体写入新日志；按现有安全日志规范只记录会员 ID、字段名和稳定错误码。
  • CRM php think member-sensitive:migrate check 只检查运行配置，不扫描会员数据；应使用部署应用实际的 PHP CLI 版本运行。确认输出的 read_mode/write_mode 后，再通过获授权的业务读取、精确查询和写入流程做定点验收。
  • 不要在当前模式执行历史 backfill --execute：代码只允许在 dual_write 下执行，且主表明文清空后已无源数据。历史 verify 虽然只读，但仍将主表明文与影子逐字段比较；主表清空而影子有值会报 DATA_MISMATCH，不能用其零错误作为当前系统健康标准。密钥轮换 rotate 是独立、受控操作，必须保留 previous 密钥直至旧版本数据完成轮换及验收；不要因日常开发直接改密钥或版本号。
  • 调整读写逻辑时，至少覆盖：单行/分页读取、手机号和证件号空值、缺影子行与坏密文、精确搜索多命中、写入后主表仍为空、两项目互读，以及对外脱敏/异常响应。上线时验证两端配置一致，并确保长驻进程已加载新配置。

快速判断： 已有会员 ID 要明文，走各项目的读取服务；只有完整手机号/证件号要找会员，走精确查询后再套业务过滤；要变更值，走统一写入及所属业务校验。任何以 t_member.phone/identity 为数据源的新代码都不符合当前模式。
