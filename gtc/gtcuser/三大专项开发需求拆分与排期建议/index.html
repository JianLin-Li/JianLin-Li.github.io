三大专项开发需求拆分与排期建议

2026-10-29 项目：gtcuser

gtcuser 三大专项开发需求拆分与排期建议

用途：以下 3 个加粗名称就是建议录入 Lark“任务名称”的需求名称；每条下面的“包含修改”可放入任务描述。本文未录入 Lark，也未修改业务代码。

依据《三大专项排查报告》（2026-10-13 至 10-14，代码基线 master）。报告是静态风险台账，不代表问题已在当前发布分支或线上复现。实施前以目标分支、实际调用量和数据库结构重新核对。

建议录入的 3 个需求

顺序 需求名称 覆盖报告编号 排期判断
1 gtcuser - 资金流程与资源使用优化 T01-T08、C01-C05、S06 P1 优先修资金事务；连接与文件资源按实测排期
2 gtcuser - 业务接口查询优化 N01-N08、N11-N16、N26-N34、N39、N41、S01-S05、S07-S12 S01 先复核；其余按调用量和 SQL 总耗时排序
3 gtcuser - 后台任务与维护命令查询优化 N09-N10、N17-N25、N35-N38、N40、N42-N45、S13-S15 P2/P3；只处理仍启用或确需运行的入口

表中一行是一条排期需求，表中名称可直接作为任务名称；顺序只是建议处理顺序，不是名称的一部分。这 3 条是排期容器，并非各自一次性上线：资金、资源、接口、任务可分别提交和验收。S05、S07、S11、S13、S14 已合入对应调用链；S06 随入金链路取证，是否建索引仍需单独审查 SQL 发布文件。

1. gtcuser - 资金流程与资源使用优化

包含修改

资金事务与入出金：

  • T01/T08：修订阅申请与结算退款的提前返回、非正金额和重复回滚；每层只结束自己开启的事务。
  • T03/T05：修系统资金流水与会员余额 Repository 在查询、计算、写入异常及 Error 下的事务闭合，核对嵌套事务所有权。
  • T02/T04/C02：修 MT 自动入金的异常出口、重复回滚和持有事务等待远程 MT 的问题；远程结果未知时按订单对账，不直接重试扣款或入账。
  • T06：使钱包提现单、跟踪记录、余额、资金明细和审核步骤在失败时保持一致。
  • T07：把入金回调的提交前失败、提交结果未知、已提交但后续 MT/明细/统计失败分开处理，建立重复及并发回调幂等和补偿路径。
  • S06：核对入金记录按会员/状态查询的实际 DDL 和执行计划；仅在收益明确时另交付索引 SQL，不改变首次入金 count 口径。

资金验收：隔离环境覆盖正常、提前返回、每个写入点异常、嵌套事务、重复/并发回调和 MT 结果未知；事务出口层级与入口一致，余额、订单、流水和远程结果可核对，资金不重复变更。入金口径变更时回归依赖该数据的后台报表。

先确认的业务口径：结算金额为 0/负数如何处理；付款或 MT 响应未知时如何对账、重试和补偿；失败记录是否独立持久化。

连接池与外部资源：

  • C01/C03：按实例、Worker、消费者及数据库目标汇总实际连接池预算；采集活跃、空闲、等待、连接错误和数据库连接峰值，再调整各池上限。配置的上限不等于实际连接量。
  • C04：分别处理公共 getData、GtcOutPay 和 Zoom 请求缺少总超时的路径；设置连接及总超时、限制重试和并发。付款超时后先对账，不能直接认定未付款。
  • C05：在 CSV 导入和下载 Job 的异常路径保证文件句柄清理；按文件规模评估导入内存峰值。此项为条件风险，按 FD/RSS 数据决定实施优先级。

资源验收：在可控压力和连续失败场景比较调整前后的池等待、连接峰值、超时、事务耗时、FD/RSS；外部等待有上界，付款状态不因本地超时被误判。不得把 Sleep 连接数量单独当作永久泄漏证据。

2. gtcuser - 业务接口查询优化

包含修改

交易、跟单与会员接口：

  • N01：当前会员当前页设备批量获取最新成功日志，保持 PC/App、在线状态和分页 total。
  • N02：按服务器与品种、账户与品种 ID 批取品种及收藏状态。
  • N03/S05：MT5 成交仅按当前页的真实 Server+Ticket 批取订单，先核实跨服务器 Ticket 归属。
  • N04/N16：PAMM 审核及列表在当前页预取持仓、策略附表和服务器；实时净值与远程请求另行计时。
  • N05：策略列表仅对当前页策略做受控分组聚合，保持状态过滤和金额精度。
  • N15/N28-N30：兑换和账户列表按服务器、账户、申请状态等复合键预取账户、跟单申请与配置。
  • N31/N33/N34：跟单列表预取服务器和冷缓存收益率，两个列表入口一起回归，利润部分已有批量读取。
  • N32/S11：修 PAMM 日回撤 0 值缓存误判；确定最大时间跨度，再按 SelectDB 真实 DDL/Profile 优化首尾值读取，保留原计算公式和时区。
  • N41：禁用证件会员检查按当前批会员复用账户/服务器读取，保留影响禁用决策的最新状态复核。

KYC、IB 与配置接口：

  • N06：按当前代理集合聚合下级数量，保持层级深度和状态过滤。
  • N07/N08/N27：佣金规则及设置标题按所需规则 ID 批取，保留佣金上下限、历史降佣校验和缺失配置的表现。
  • N11-N14：KYC 表单、子类型、认证内容与快照按当前会员/表单/类型批取，保留通过状态、历史版本、auto 规则和展示顺序。
  • N26：服务器配置批取，公共配置只作为原有优先级下的回退。
  • N39/S07：对当前会员和分组候选批取申请并匹配；核对真实索引后评估 member_id+status 过滤，不用简单子串替代 CSV 分组规则。

搜索、层级与分页 SQL：

  • S01：转账候选查询增加有界返回或分页；数字账户优先精确定位；核对权限后评估以祖先/后代关系替代 FIND_IN_SET(path)。
  • S02/S08：IB 关键词检索评估数字 ID 等值查询、文本搜索方案和列表/count 成本；保留祖先权限、中文/大小写语义及已有页大小约束。包含搜索是否改为前缀须先取得产品口径。
  • S03/S09：SelectDB 资金历史与账户关键词查询优先评估会员/账户等值条件和业务时间范围，依据目标表 DDL、分区/Tablet、同次 Query ID/Profile 决定是否需要倒排索引。
  • S04/S10：配置 CSV 匹配先测配置表规模、server/status 过滤和 JOIN 放大；小表优先受控批取或缓存，大规模才评估规范化关系，并保持配置刷新。
  • S12：对具体高成本入口分别评估页大小、count、offset 和 total 契约，不在公共 BaseModel 上全局硬改。

验收：优先按调用频率和 SQL 总时间选择接口；比较 1/10/20 条（品种可用 100 条）时的 SQL 指纹、次数和总时间。列表内容、权限、服务器归属、分页、状态和金额精度逐项与原行为一致；KYC 认证结论、表单快照、IB 层级及佣金配置、分组授权范围不变。各接口可分别提交，不需要一次改完本需求全部入口。拟优化的 SQL 需记录脱敏查询、连接引擎、实际索引、过滤条件、扫描/返回量和同参数前后计划及耗时；只有计划证实收益的索引或结构变更才生成独立版本 SQL 并同步数据字典。并非所有 S 编号都必然需要修改代码。

3. gtcuser - 后台任务与维护命令查询优化

包含修改

  • N09/N10：IB 邮件按当前批次预取会员、父级及下级，保持收件范围、邮件内容与发送去重。
  • N17-N21/N35：仍启用的策略、利润与状态任务按当前批策略 ID 预取附表；N17/N18 原文件在当前发布分支已删除，先追踪替代链路，未找到可达路径则不开发这两项。
  • N22/N40：风控自动移组按批预取服务器、会员账户和已处理复合键；保留数据库幂等或原子状态校验。
  • N23：返佣日志任务按伙伴/客户/账户复合键批取配置，保留返佣计算与写入语义。
  • N24/N25/N36/S13：PAMM 结算、告警和订单历史任务按批预取账户、copies 与转账日志；先测历史扫描/返回比，再决定游标方案，不能丢迟到或回补订单。
  • N37/N38：日历和分组同步按本批业务键预取，批量写入前核对唯一约束、语言/服务器维度、模型事件及配置缓存刷新。
  • N42：IB 祖先上传事件复用可合并的下级读取，但保留各祖先独立上传范围。
  • S15：账户历史同步先核对 CONCAT 不等比较与删除异常记录的业务语义，再考虑分批校验或查询优化。
  • N43：PatchFollowMttype 在每批信号与 copy 范围内按复合键预取配置和账户。
  • N44：CheckPammShare 按批预取策略附表、份额汇总及 copies，保持原精度。
  • N45/S14：PatchGtcData 先限定待修复会员、业务键与日期范围，减少 SelectDB 按 memo 大范围检索；记录预计读写数量并核对资金归属。
  • 三个手工 Command 先确认是否还会运行；若均已废弃，记录结论，不安排开发。

验收：逐任务确认是否启用、单批数量、读写及远程耗时和积压；重复运行、并发及迟到数据下结果一致，批内可批量读取次数有界。处理前状态复查、结算幂等和远程实时核验不能为降低查询数而删除。手工命令只在隔离数据中核对修复对象、账户归属、份额与资金精度，不在生产执行性能验证。

所有需求的共同前置与排除项

  1. 先确认目标发布分支、入口调用频率、任务是否启用、数据库实际索引和 SelectDB DDL。报告中的 73 个编号不是 73 个独立 Bug，更不是一次性上线清单。
  2. 资金测试在隔离环境覆盖正常、边界、异常、重复和并发；N+1 任务以 SQL 次数及业务结果双重验收；SQL 任务需同参数前后计划与耗时证据。
  3. B01-B08、报告已排除的误报及未证实可达的候选不直接列入开发范围。下载中心提交后投队列失败、退款余额先于事务、跨连接 setBalance 等未编号线索，确认可达性和影响后另行立项。
  4. Git blame 只用于寻找熟悉历史代码的协作者，不作为 Bug 责任或排期归属依据。涉及数据库结构时按 gtcuser 规范交付独立版本 SQL、数据字典更新、回滚与跨服务回归。
