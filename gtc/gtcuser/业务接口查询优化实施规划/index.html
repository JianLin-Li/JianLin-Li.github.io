gtcuser 业务接口查询优化实施规划

规划日期：2026-10-19。目标分支：feature/v2.20.0/api-query-opt，当前基线：6ced4a219。本轮只形成实施规划，未修改业务代码、SQL 或线上配置。

依据《三大专项排查报告》和《三大专项开发需求拆分与排期建议》。报告是 2026-10-14 的静态台账；以下编号用于追踪，不等于每项都已在线上造成慢查询，也不等于全部需要改代码。

目标和范围

本需求覆盖 N01-N08、N11-N16、N26-N34、N39、N41，以及 S01-S05、S07-S12。目标是在保持接口字段、权限、分页 total、状态、金额精度和服务器归属不变的前提下，减少当前页内可合并的重复读取，并处理经执行计划证实的高成本 SQL。N03/S05、N39/S07、N32/S11 是同一调用链的两类证据，不当作独立接口重复开发；其中 N03 的跨服归属修正与查询批取仍须分别审核。

当前分支抽查仍能定位 N01 设备日志逐条查询、N02 品种和收藏逐条查询、N03 按 Ticket 查订单、N05 逐策略聚合、N39 会员乘分组的 exists、N32 日回撤逐日读取及 0 值缓存误判、S01 转账候选无界读取。其余编号开始开发前逐条复核入口是否仍可达及是否已被其他改动处理。

仓库字典显示：t_member_login_log 有 (member_id, device_id, login_status) 索引；t_cross_mt5_orders 的主键是 (Server, Ticket)；t_symbol 未见以 server_id 开头的索引；t_member_group_apply 只有主键。以上均是仓库基线，实施前还需核对目标环境真实 DDL。S08 的当前 OpenGroupListService 使用 SELECTDB 连接，和报告中的 MySQL 描述不一致，应以当前连接、目标库 DDL 和 Profile 为准。

执行顺序

阶段 覆盖 交付判断
0. 复核与基线 全范围，优先 S01、N02、N01 确认入口、调用量、SQL 总耗时、权限与实际 DDL，选定需要实施的项
1. 首批低风险批量读取 N02、N01 两个接口可分别提交、分别回归，建立查询次数和结果对照方式
2. 转账候选查询 S01 先确认返回范围与前端契约；有界读取方案单独评审，证实高成本时可提前到阶段 1 前实施
3. 交易、策略与跟单列表 N03/S05、N04-N05、N15-N16、N28-N31、N33-N34 按实际热点逐接口提交，先解决复合键归属，再优化批量读取
4. KYC、IB 与会员校验 N06-N08、N11-N14、N26-N27、N39/S07、N41 保留历史版本、佣金规则、层级权限、禁用决策及配置回退语义
5. 复杂 SQL 与 SelectDB N32/S11、S02-S04、S08-S10、S12 同参数执行计划和总耗时证明收益；无证据或需改产品搜索口径的项暂不改
6. 联合回归与交付 各阶段已实施项 分入口验收、检查 SQL 发布材料、记录剩余风险和回滚顺序

阶段顺序不要求把所有编号一次完成。阶段 0 如果发现 S01 在高频场景产生大量无界结果，先处理阶段 2；若暂无证据，先交付 N02、N01。一个接口或一条调用链形成一个可回滚提交，不把本需求做成一次大范围重构。

小步实施与审核规则

下面的 0.1、1.1 等是实施和审核单元，不是新的排期需求。同一阶段的小步也不合并成一次代码修改；同一编号若有两种独立查询（如 N02 的品种与收藏），分别改、分别验。若两个入口共用同一个必须修改的方法，先查全量调用方，一次修改并同时回归所有受影响入口，不人为拆出两个相互依赖的提交。阶段 3-5 的顺序以阶段 0 的实测热点调整，未证实有收益的小步可以记录证据后跳过。

每个代码小步按以下顺序执行，并在用户审核本步代码后才进入下一代码小步：

  1. 改前确认：固定目标分支和工作区状态；从入口追到 Service、Repository/Model、权限、数据字典和测试，记录一份脱敏请求、原响应及 SQL 次数/耗时。对拟改方法及其底层 Repository/Model、Trait、缓存注解、公共函数搜索所有静态调用方，再检查 DI/事件/任务等间接入口；列出读者、写者、缓存键、响应及副作用。静态检索不能证明不存在动态调用，未知项列为未确认。明确本步只涉及哪些文件、查询及返回字段。
  2. 只改本步：优先限定在现有业务方法及其直接数据访问层；只处理当前页/当前批的查询。若发现必须改公共基类、共享 helper、接口字段、权限、配置、数据库结构或其他项目，暂停本步并先单独评审影响范围与回滚方案。
  3. 本步验证：用本机 PHP 8.1 解释器对每个修改的 PHP 文件执行 -l，只运行本步逻辑及实际受影响调用方的 PHPUnit 测试文件/方法，再做必要的隔离环境接口对照；按相同参数比较结果、SQL 指纹次数、数据库总耗时、接口耗时及峰值内存。逐条 SQL 核对实际数据库连接和引擎；不因其他历史测试失败而误判本步，也不因本步测试通过就宣称全量回归通过。测试不能证明性能或环境不具备时，明确写“未验证”。
  4. 交用户审核：给出本步差异和下表所列交付说明；用户确认后再进入下一步。若结果不一致，停在本步修正或回退，不让问题叠加到后续阶段。

每步的交付说明固定为：改了什么（文件、方法、查询及差异）、目的是什么（消除哪次重复读取或哪段高成本扫描）、影响范围（入口、字段、权限、数据/配置/前端）、验证结果（通过、失败、未运行及证据）、剩余风险与回滚。一个小步对应一组易审查的差异；能独立提交时才形成一个独立提交，不以“阶段完成”为理由打包不相关改动。

Hyperf 兼容与性能方案准入

composer.json 声明 PHP >=8.1、Hyperf 3.1.*，项目规范要求修改保持 PHP 8.1 兼容。本机 PHP 8.1.34 在 /opt/homebrew/opt/php@8.1/bin/php，已验证可执行 -l；终端默认 php 是 8.5，不能用于证明 8.1 语法兼容。每一步实施时先核对目标部署 PHP/Swoole 与锁定依赖；只使用 PHP 8.1 支持的语法及本仓库 Hyperf 3.1 已提供的 Query Builder、Model、缓存和协程 API。新用框架方法要在当前 vendor 源码或现有用例中确认签名、连接归属、返回类型和异常行为，不凭别的 Laravel/Hyperf 版本经验套用。

PhpStorm 项目语言级别已配置为 PHP 8.1，PHPUnit 配置指向 phpunit.xml.dist 和本地 vendor/autoload.php；现有“gtcuser 单元测试”运行配置默认覆盖整个 tests/Unit。实际验证本需求时选本步对应的测试文件或方法，并补测被修改共享方法的受影响调用方，不直接跑整个目录或全量套件。记录 PhpStorm 实际选用的 PHP 解释器、测试命令/范围和结果。当前本地 vendor/composer/platform_check.php 要求 PHP >=8.2；若用 PHP 8.1 启动现有 vendor 的 PHPUnit 被依赖平台检查拦住，不能绕过检查伪造通过。仍执行 PHP 8.1 语法检查，在兼容的测试解释器下做针对性行为测试，并把“PHP 8.1 下的单元测试未运行”单独列为限制。

在写代码前，为本步形成候选方案对照：现状、最小局部改法，必要时再列索引/缓存/结构方案。先通过业务结果、权限、并发和缓存语义筛掉不等价方案，再比较性能；不能因为查询次数下降就认定更快。选型至少记录同参数、同权限、同连接引擎的 SQL 次数、扫描/返回行数或 SelectDB 扫描量、数据库总耗时、接口耗时、峰值内存、冷热缓存及 1/10/20 项规模变化。能在隔离环境复测时再比较执行计划和并发下连接池等待；无法取得真实证据的方案保留为假设，不承诺收益。

候选方式 可能适合的条件 何时不采用或必须另审
保留现状 接口低频、表小、缓存命中高，实测数据库总成本很低 不为了完成报告编号而改代码；记录暂缓证据
当前页/当前批 whereIn 批取 原查询按稳定业务键定位，批次有上限，索引能利用，结果可逐行等价映射 键不唯一、first() 无稳定选中行、批取读出远多于所需数据、超大 IN 参数或峰值内存明显上升时暂停；必要时只对当前批分块
受控集合分组聚合 原来逐项 sum/count，且能先用当前页 ID、状态、时间和服务器缩小驱动集 需对大表先全量 GROUP BY、金额精度/空值变化、索引不能支持过滤时不采用；与原逐项查询比较总扫描成本
局部缓存或复用 数据允许相同的新鲜度，已有缓存键、TTL 与失效规则可保留 登录在线状态、禁用决策、资金候选、KYC 写入、配置即时刷新等不能为减少 SQL 自行延长缓存；跨请求缓存须单独评审
精确定位/有界搜索、分页 原产品契约允许，且筛选范围与权限可证明一致 子串搜索改等值/前缀、无界结果改截断或 total 变化均属接口行为修改；先确认前端和产品口径，再独立交付
新索引或关系结构 真实 DDL、选择性与同参数执行计划证明现有方案仍高成本 写入放大、DDL 锁、共享数据库其他读写者、SelectDB 物理结构未核实时不落地；独立 SQL、数据字典和回滚方案另审

执行方式遵循本项目分层 app/Http -> app/Service -> app/Repository/Model；用户输入继续参数绑定，动态库名只来自可信配置，MySQL 与 SelectDB 分别验证 SQL 方言和执行计划。测试可沿用 PhpStorm 的 PHPUnit 配置；终端执行时使用项目 co-phpunit/tests/bootstrap.php，且只指定本步测试文件/方法。数据库测试先确认只连对应引擎的隔离环境；代码修改后用上述 PHP 8.1 路径做语法检查，行为测试另按实际解释器如实报告。

每步代码审核前增加一张方案选择卡：原 SQL/调用次数及索引、候选方案与预期代价、为何排除其他方案、实际前后计划/耗时/内存、结果等价证据、PHP/Hyperf 兼容检查、未验证项。业务结果不一致或总成本无稳定改善时，停在本步并保留现状。

数据库连接边界

下表仅说明当前代码选择的逻辑连接，不把连接名或 mysql 协议驱动当成目标环境物理引擎的证明。config/autoload/databases.php 中 default、selectDB、bigdataDB 是不同连接；selectDB 还配置了不同的读/写目标，读目标注释明确用于 SelectDB。目标环境的真实目标库、表结构和同步时效必须在每步取证时核对，不在文档中记录主机或凭据。

查询范围 当前代码连接证据 实施限制
N01 登录日志、N02 品种/收藏、N03 MT5 订单、N33/N34 收益率总表、N39 分组申请、S04 配置查询 对应 Model/Repository 未显式指定连接，按 default 查询；MemberHourCountTotal 的 selectDB 声明是注释，不是生效配置 先按默认 MySQL 的实际 DDL/索引审查；不得为借用 SelectDB 读表而改连接或改变数据新鲜度
N32/S11 日回撤、S03 资金历史、S02 IB 代理搜索、S08 开户组列表、S09 代理账户搜索 MemberHourCount、FundDetailSelect 显式设 selectDB，其余入口显式 Db::connection(SELECTDB) 以该方法发出的读 SQL、目标 SelectDB DDL/分区/Tablet/Profile 为准；不能套用 MySQL 字典索引或 MySQL 才有的优化方式
S01 转账候选、S10 风险组/开户组以及交易账户相关查询 默认连接上还可能拼接按服务器选择的 MT 数据库表；同一接口可同时读取默认库、MT 库或 CRM 服务 逐条记录查询发生的连接与服务器库名来源；不能把跨库 SQL 随手迁到 selectDB，也不能假定可跨不同连接直接 JOIN 或保持同一事务/实时性
同一个 Model 的其他方法及报告入口 MemberHourCount 虽默认使用 selectDB，部分方法显式 setConnection(DEFAULT)；IB 报告其他方法还使用 bigdataDB 只按本次修改的方法/SQL判断，不能按类名、表名或同文件其他查询推断；bigdataDB 与 selectDB 分别取实际计划

每步的 SQL/连接清单必须写明：入口、所在方法、Model 或 Db::connection(...)、实际读/写路由、目标环境的数据库引擎和表、现有过滤条件与索引/分区、同步延迟要求、拟采用方案是否保持原连接。若拟改 SQL 会切换连接、读写目标或跨库数据来源，先独立评审数据一致性、权限、执行计划和回滚，不当作普通查询优化继续实施。同参数前后性能对比必须落在同一引擎与等价数据范围；MySQL 用其真实 DDL/索引及 EXPLAIN，SelectDB 用其真实 DDL、分区/Tablet 与 Profile。

改前影响范围复核结论

以下是基于 gtcuser 当前 6ced4a219 源码和仓库数据字典的静态复核，不是线上数据、执行计划或动态调用全覆盖证明。标为“先停”的项目必须在动代码前解决口径；纯查询优化不能顺手修历史业务规则。

编号/步骤 已确认的耦合与逻辑风险 改动前必须核对的影响范围
N02 / 1.1-1.2 TradeService::tradeSymbolInfo 的未登录分支直接返回 MT 数据；已登录分支先校验账号归属和本地服务器。t_symbol 字典只有 (symbol,type) 唯一约束，不能保证 (server_id,symbol) 唯一；当前 first() 无显式排序。收藏当前只按 login_id、symbol_id 判断。 只改已登录分支的展示查询；先查重复品种和选择结果，不用 keyBy 任意覆盖；收藏批取不得悄悄增加 member_id 条件、改变布尔类型或 SVG/MT 调用。重复行无法确定原选择时先停。
N01 / 1.3 loginDevice 取最新成功日志后逐条实时 checkTokenOnline，无日志时还输出一组空字段；日志 id DESC 决定选择。 只替换日志读取；设备分页、total、当前设备、token 实时判断、空字段及并发删日志结果逐项对照。不得改通用 MemberLoginLogRepository::findByFilter。
S01 / 2.1-2.4 CashService 根据转账开关、团队层级和 CRM 精确手机号结果决定钱包/MT 候选；MT 分支跨服务器拼接 UNION，返回给选收款人的调用方。 先停：确认前端是否要求全量、关键词包含范围和手机号故障返回；限制数量、分页或替换层级关系都属于契约/权限改动，独立评审，不在优化中静默截断。
N03/S05 / 3.1a-3.1b 成交当前按 PositionTicket 查订单，字典订单主键为 (Server,Ticket)；补充 Server 可改变现有 OPEN_TIME，不只是减少 SQL。 先停：用跨服相同 Ticket 证明成交 Server 与订单 Server 的映射；把“修正归属”和“当前页批取”分别列差异和测试，不能把结果变化当作纯性能等价。
N04-N05、N16 / 3.2-3.4 PAMM 审核、策略净值与展示列表各有状态、金额精度和远程 MT 分支；N05 原聚合只算 status=1，N16 原逐条读取的是服务器。 各入口分别查条件与查询列；只批取当前页真实需要的数据。缺记录、同策略重复、聚合 0/null、实时净值和远程异常不能因映射/缓存而变。
N15、N28-N31 / 3.5-3.9 兑换和跟单列表按服务器、login、状态等组合键区分；N28 的 findPendingOrApproved 对状态 0/9 用无排序 first()；N28 账户在线状态还依赖 update_time 与当前时间。 先检查重复申请、同 login 跨服以及单条查询的选中行；映射不能任意覆盖。保留外部账户、本地账户、申请优先级、在线状态实时计算与远程分支；不能为了批取改共享 Repository 的返回规则。
N33-N34 / 3.10-3.11 两个跟单列表共用带 60 秒 Cacheable 的 MemberHourCountTotal::getEarningRate；公式中 0 入金返回 0，调用方再 sprintf('%.2f')。 查所有调用方及缓存键；批量读取不能绕过热缓存后改变新鲜度、公式、精度或返回字符串。共享方法若修改必须同时测两个入口及缓存冷/热场景。
N06-N08、N27 / 4.1-4.4 代理下级计数与佣金规则分别影响层级和金额校验；标题查询的缺失配置和状态也影响错误/展示分支。 逐入口保留代理集合去重、深度、有效状态、规则 ID、佣金上下限及异常结果；只在原作用域批取，不改公共佣金计算。
N11-N14 / 4.5-4.8 getMyInformationGtc 对已通过会员可能先返回资料快照；buildKycFormDetail 同时用于页面展示和多处认证快照写入。 先停：读路径与写快照路径分别画调用图；优先在展示入口局部预取，不能直接改共享表单构建方法的输出、翻译时机、题目排序或持久化快照结构。任何共享方法变更须覆盖全部写入路径。
N26 / 4.9 ConfigServerService::getConfigValue 先服务器配置，缺失才取启用的公共配置，当前 openMtserverlist 逐服务器调用；该公共方法还有独立语义。 优先在 openMtserverlist 局部批取，保持“配置存在但值为 0/空”与“配置不存在”的区别；公共回退只按原条件发生，不改全局配置缓存/刷新。
N39/S07 / 4.10 IbService::getApplyGroup 是先 exists 再 insert 的写流程，原 LIKE '%组名%' 含数据库排序规则及 %、_ 通配语义；精确 CSV 或 PHP 子串判断都不天然等价。 先停：先用隔离数据证明替代查询与原 SQL 对每个会员/分组的判定一致；核对重复/并发申请、状态 0/9、批量插入及重试。不能因读取优化增删申请或扩大授权。

S02/S08、S03/S09 / 5.3-5.6 IB 搜索含祖先权限、数字 ID 子串、文本包含、count 与游标/普通分页；资金历史和账户搜索还含会员/账户范围及 SelectDB 特定条件。 先停：数字 ID 改等值、文本改前缀、增加必填时间或改变 total 都可能减少结果；先做原结果集合与权限对照，再分别取实际连接引擎的计划/Profile，不复制已有动态 SQL 拼接到新查询。
S04/S10 / 5.7-5.8 S04 是 AccountRegisterSettingRepository 的组 CSV 查询和 ConfigMemberNameRepository 的国家代码查询两条链；后者单值精确优先、CSV 回退。S10 的配置组 JOIN 参与账户风险组/开户组判断。 配置表大小、候选顺序、server/status/currency、单值优先和刷新时机分别审核。组命中多条时不能用无序 map 改选中记录；关系规范化/DDL 单列。

  • S12：逐个高成本入口拆开测列表查询和 count，确认页大小、offset 与 total 依赖；只优化具体接口，不直接全局改 BaseModel::page。

完成标准：每项提供同参数、同连接引擎的前后执行计划、扫描/返回量及数据库总时间。无明显收益的结构修改暂不实施；如确需索引或表结构，新增 scripts/v2.20.0/ 下本需求独立版本 SQL，同步 docs/数据字典.sql，说明写入成本、发布及回滚方式。

小步 最小改动及目的 审核关口
5.1 N32/S11 缓存 只修 0 值被误判为未缓存的条件 0、非 0、冷/热缓存及返回公式一致；独立审核后才考虑查询改写

统一验证与交付边界

  1. 每个小批次先读对应 Controller、Service、Repository/Model、数据字典和已有测试；修改 PHP 后执行 php -l 及针对性行为测试。数据库/SQL 测试只在确认隔离环境后运行；回归覆盖空结果、边界、权限、历史数据、重复调用和冷热缓存。
  2. 分别统计 SQL 指纹次数、数据库总耗时及接口耗时。只有结果一致且相关成本下降才算通过；远程 MT/CRM 时间、连接池等待与 SQL 时间分开记录。
  3. 大表读取先用会员/账户、服务器、ticket、状态和时间缩小范围，再检查真实索引与计划；列表用当前页，聚合只作用于受控 ID 集合。深分页或全量 count 的改动须保持现有 total 契约。
  4. 不改统一返回结构、公共分页基类、全局搜索语义或数据库公共字段。若证据表明必须改这些公共边界，先另行评估影响接口、前端兼容、发布与回滚，再决定是否纳入本分支。
  5. 每一组独立提交、独立回归；问题若已消失、入口不可达或实测成本低，记录证据后关闭该编号，不为了完成编号而改代码。上线时先发布无需 DDL 的接口改动；确需结构变更时按独立 SQL 的依赖顺序执行并保留回滚方案。

阶段 6：联合回归与交付的小步

小步 做什么 审核材料
6.1 汇总每个已审核小步的改前/改后响应、SQL 次数与总耗时 逐入口结果和未实施编号的原因
6.2 按已修改入口做组合回归，重点覆盖权限、跨服、KYC、资金候选、缓存、分页和错误分支 通过/失败/未运行清单，不能用单接口测试替代组合验证
6.3 核对实际代码、独立 SQL、数据字典、配置和部署依赖 逐项发布及回滚顺序；未获批准的 DDL 不发布
6.4 最终由用户审核完整差异，再决定合并或发布 各小步审查记录、剩余性能风险和回滚方式

当前未取得线上调用量、真实 DDL、MySQL 执行计划及 SelectDB Profile，也未运行隔离库性能基准。因此阶段 3-5 的最终实施顺序要由阶段 0 的数据决定，不能从静态报告直接承诺所有条目都改或指定性能提升百分比。
