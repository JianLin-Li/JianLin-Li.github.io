gtcuser 业务接口查询优化：阶段 0 复核与 1.1 审核记录

2026-10-19；目标分支 feature/v2.20.0/api-query-opt，基线 6ced4a219。本轮已实施 1.1 品种读取小步；未修改数据库结构、配置、权限或其他查询小步，尚未提交，等待代码审核。

本轮结论

  1. N02 / 1.1 品种读取已实施。 TradeController::symbol_info 只在已登录且账号归属、本地服务器校验通过后进入本地品种查询。原方法对每个 MT 返回的品种，以 symbol + mtserver 查 symbol 表的无排序 first()；未登录分支直接返回 MT 数据。staging 实际存在同服务器同品种重复行，所以本步只复用批取中严格同名且唯一的行；重复、缺失或排序规则别名仍执行原 first()。SVG 已批取，收藏查询属于后续 1.2，本步不碰。
  2. N01 / 1.3 设备日志暂不改代码。 MemberController::loginDevice 调用 TMemberService::loginDevice；后者只遍历当前页设备，逐设备按会员、设备、成功状态取 id DESC 第一条日志，然后实时检查 token 在线状态。字典有 (member_id, device_id, login_status) 索引。简单地对设备 ID 使用 whereIn()->get() 会读出所有历史日志，不能据此断定比现状便宜；分组 MAX(id) 或相关子查询须看真实 DDL、数据分布及执行计划。设备页、total、无日志空字段、当前设备和实时状态均不得改变，也不应修改共用的 MemberLoginLogRepository::findByFilter。
  3. 数据库边界已核对。 上述品种和日志 Model 均未指定连接，沿用 default 的 MySQL 连接；不涉及 selectDB 或 MT 分库查询。已用 .env.staging 的 DB_* 配置直接连接 staging MySQL，并核对当前库与配置一致；本次直连验证在只读事务内执行，没有使用 DB_*_SLAVE1 或 MT 分库配置，也没有写库。

数据与执行计划

  • staging t_symbol 有 5,068 行、3 组 (server_id, symbol) 重复键；实际索引为主键、唯一键 (symbol, type) 和普通索引 type，与仓库字典一致，没有 (server_id, symbol) 唯一键。
  • 同一服务器的样本 EURUSD 只有 1 行，XAGUSD.c 和 XAUUSD 各有 2 行。旧查询对样本 XAUUSD 选中 id=4845；批取返回两个 XAUUSD 行。此处必须回退旧查询，不能用 keyBy 覆盖。
  • 相同服务器及品种样本的 EXPLAIN：旧单品种查询使用 idx_type_symbol，直接连接本次估计扫描 10 行；3 个品种批取仍使用该索引，估计扫描 28 行。此前 Navicat 对旧查询估计为 9 行，均属于优化器估计，可能随统计信息变化。批取主要节省往返次数，尚不能据此断言接口总耗时下降。Navicat 单次结果时间约 0.03 秒，仅供参考，不是同请求接口基线。
  • 以服务器 31 的真实品种名分别取 1、10、20 个键做只读对照，每组均包含重复的 XAUUSD：候选批取 SQL 分别返回 2、11、21 行，每组仅该重复键需要原 first()；三组所选 symbol_id 与逐品种旧查询的差异均为 0。实际代码在只有 1 个品种时不执行批取，仍只走原单条查询。这只验证本次样本中的本地品种 ID 选择，不等同于完整接口响应或性能验收。

1.1 改动与验证

  • app/Service/Trade/TradeService.php：已登录分支仅对当前 MT 返回键按最多 100 个一批读取本服务器的 id,symbol；严格同名且唯一时复用，其他键继续执行原查询。只有 1 个品种时保持原单条查询。权限、MT 请求、SVG、收藏查询、响应字段和未登录分支未改。
  • tests/Unit/Trade/TradeSymbolInfoBatchLookupTest.php：验证唯一命中可复用、重复多行只回退歧义键、排序规则别名使整批回退。PHP 8.2 的定向 PHPUnit 连同原 SVG 测试共 4 个测试、10 个断言通过；两处修改的 PHP 文件均通过 PHP 8.1 -l，git diff --check 通过。
  • .env.phpunit 本地测试库认证返回 MySQL 1045；数据库只读验证先使用与 .env.staging 一致的 Navicat 连接，随后直接用该配置建立 PDO 只读事务复核数据、索引、执行计划和 1/10/20 品种 ID。PHP 8.1 下 PHPUnit 未运行：当前 vendor 平台检查要求 PHP 8.2 以上。首次尝试的 co-phpunit 在 Hyperf 扫描阶段因 pcntl_fork() 不可用中止，随后改用 PHP 8.2 普通 PHPUnit 完成上述定向测试。
  • 尚未取得脱敏的真实 symbol_info 请求与原响应，因此接口整体返回逐字段对照、1/10/20 品种的 SQL 总耗时、接口耗时和峰值内存未验证。这一步没有写库、缓存或配置副作用；若审核发现结果不一致，仅撤回本步 Service 和对应测试文件即可，无数据库回滚。
